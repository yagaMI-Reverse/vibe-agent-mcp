# Границы решения — что агент не умеет и где сломается

Честно, без приукрашивания: это тестовое, отлаженное на бюджете 453₽,
дошедшее до 72₽ живыми платными вызовами на двух разных лендингах. Ниже —
то, что реально проверено, и то, что нет.

## 1. [РЕШЕНО] Переформулировка `utp` не чинит систематический дефект генератора

Живой прогон 31.07.2026 ([runs/2026-07-31_live](../runs/2026-07-31_live))
показал: когда агент добавлял в `utp` инструкцию «каждый заголовок строго до
56 знаков», брак **вырос**, а не упал — 90 → 111 → 153 из ~150 комбинаций,
три итерации подряд.

Гипотеза: `direct/ads-generate` использует `utp` как контентное УТП
(что писать), а не как мета-инструкцию форматирования (как писать). Текст
инструкции сам становится материалом для заголовков, а не ограничением на их
длину. Это тот же системный дефект генератора, который был найден в первом
тестовом (34% заголовков 58–59 знаков при лимите 56) — он не лечится со
стороны клиента API, только со стороны промпта самого генератора.

**Исправлено 01.08.2026**: вместо просьбы генератору — локальный фиксер
(`orchestrator/run_agent.py:apply_local_fixes`), который механически обрезает
по границе слова только те объявления, где единственная причина брака —
превышение длины, и пересчитывает вердикт. Переформулировка `utp` оставлена
только для содержательных дефектов (непроверенные обещания), для которых
она реально помогает — на прогоне 01.08 сняла 9 из 9 галлюцинаций за одну
итерацию. Результат: 0 БРАК, 0 ГАЛЛЮЦИНАЦИЯ за 2 итерации вместо честного
поражения за 3. Подробности и цифры — в README, раздел «Локальный фиксер
длины». Остаточная оговорка: обрезка по слову иногда обрывает мысль на
полуслове — грамматически корректно, редакторски не идеально (см. пункт 8).

## 2. Нет бесплатного dry-run для платных direct/*-вызовов

`/generate/estimate` бесплатен только для общей мультимедиа-фабрики
(image/video/text/voice/music) и для проверки `brand_id`-инъекции. Для
`direct/ads-generate`, `direct/landing-audit`, `direct/sitelinks`,
`direct/forecast` цена фиксированная и известна заранее из `/capabilities` —
поэтому бюджетный гейт в этом решении сравнивает потрачённое с этой таблицей
цен, а не делает pre-flight-запрос к API перед каждым платным вызовом. Если
Вайб-Маркетолог сделает цены на direct/* переменными (например, по объёму
текста), этот гейт устареет и его придётся переписать под настоящий estimate.

## 3. Бренды не участвуют в генерации объявлений

`direct/ads-generate` принимает только `url`/`utp`, не `brand_id`/`product_id`
— несмотря на то, что `/api/agent/brands` работает и в системе есть полноценный
Brand Voice. MCP-инструменты `list_brands`/`get_brand` реализованы (бесплатны,
проверены на живом API), но в текущем оркестраторе они не подключены к циклу
генерации — они могут только дать текст для ручной/автоматической сборки
`utp`, но это не сделано автоматически (не было брендов на аккаунте для теста).

## 4. [ЧАСТИЧНО РЕШЕНО] Проверено на своём демо-магазине, не на реальном клиенте

Первый живой прогон был только на `vibemarketolog.ru` — лендинге самой
платформы. 01.08.2026 добавлен второй лендинг:
[cosmetics-demo-shop](https://github.com/yagaMI-Reverse/cosmetics-demo-shop),
свой демо-магазин косметики (не лорем-ипсум, реальные проверяемые обещания —
скидка 20%, доставка 2-4 дня, гарантия 6 месяцев), задеплоенный отдельно на
GitHub Pages. Это доказывает переносимость на другой домен/контент, но не
на настоящий действующий интернет-магазин с реальной посещаемостью, SEO-
историей и живым каталогом — взять чужой реальный бизнес без их согласия для
теста было бы неуместно. Собственный демо-сайт — осознанный компромисс, а не
то же самое, что независимая внешняя проверка.

## 5. `/agent/list`, `/agent/message`, `/api/agent/inbox`, `safety-check`
не задействованы

Проверено вживую: `/agent/list` отдаёт `404 not_found` для этого токена (не
403 — то есть не вопрос скоупа, а недоступность метода). `safety-check`
рассчитан на реальные кампании Яндекс.Директа (`campaign_id` обязателен) — у
аккаунта таких кампаний нет и не может быть без партнёрского доступа. Ни один
из этих эндпоинтов не используется в решении — задача не требовала реального
управления рекламным кабинетом, только генерации и контроля качества текста.

## 6. Один аудит на прогон, без ретроспективной сверки score

Из-за бага в первой версии кода (см.
[runs/2026-07-31_live/report.md](../runs/2026-07-31_live/report.md), раздел
«Landing-audit») числовой score аудита для этого конкретного прогона не был
прочитан. Баг исправлен в коде, но повторный платный вызов ради красивого
числа в отчёте не делали — это было бы приукрашиванием, а не честным отчётом.

## 7. Ретраи и rate-limit — только по документации, не нагрузочно протестированы

Backoff на 429/503 и уважение `Retry-After` реализованы по пунктам из брифа
(1→2→4→8с), но за весь тест ни разу не встретился ни 429, ни 503 — код
backoff не был реально прогнан через живой rate-limit. Это код «по
спецификации», не «проверенный под нагрузкой».

## 8. [РЕШЕНО] MCP-сервер не был проверен как настоящий MCP-сервер

До 01.08.2026 сервер был проверен только прямым импортом Python-функций —
это доказывало, что код работает, но не что MCP-протокол (stdio-хендшейк,
`tools/list`, `tools/call`) работает. Исправлено: `claude mcp add` +
health-check (`✔ Connected`), и отдельно — настоящий MCP-клиент
(`mcp.client.stdio`) выполнил `initialize` → `tools/list` → `tools/call` и
получил реальные данные с живого API. Подробности — в README, раздел
«Проверено: MCP-протокол end-to-end». Не проверено: реальный разговор с
Claude Code, где МОДЕЛЬ (а не скрипт) сама решает вызвать инструмент —
вложенный `claude --print` в этой песочнице не авторизован, а
`--dangerously-skip-permissions` блокируется классификатором. Разница
между «клиент по протоколу вызвал инструмент» и «модель сама решила его
вызвать» не закрыта.

## 9. Локальная обрезка длины — механически корректно, редакторски нет

Фиксер обрезает заголовок/текст по границе слова до лимита — это гарантированно
проходит модерацию по длине, но не проверяет, не оборвана ли мысль
(«…в одном» вместо «…в одном месте»). preflight после обрезки помечает такое
объявление ГОДНО/ИСПРАВИМО, хотя человек-редактор мог бы его отклонить по
вкусу. Для реального запуска кампании нужен ещё один уровень — либо
человеческая вычитка почищенной выдачи, либо более умная обрезка (просить
модель сократить смысл, а не механически отрезать хвост) — не реализовано,
осознанный компромисс ради 0₽ и предсказуемости.
